import { launch } from '@xiaoxiaofeihh/chromix';

const browser = await launch();
try {
  const page = await browser.newPage();
  await page.goto('https://example.com');
  console.log(await page.title());
} finally {
  await browser.close();
}

在 GitHub 提问↗
Chromix 是什么？+

Chromix 是开源的定制 Chromium 浏览器，提供 Python 与 Node.js SDK。它为获得授权的自动化、兼容性测试及研究提供可配置浏览器环境，不是托管浏览器服务。

还能继续使用 Playwright 吗？+

可以。SDK 的 launch 函数返回 Playwright 浏览器对象，可继续使用熟悉的页面和上下文 API。具体参数兼容性与平台限制请查阅 SDK 文档，不应假设所有场景都能无修改替换。

首次启动会下载最新浏览器吗？+

不一定。已发布的 Python SDK 152.0.7977.82.post4 和 Node SDK 0.1.4 将 Windows、Linux 两种架构的 stable/latest 均映射到 v154.0.8037.97。macOS 保留 stable v151.0.7922.173 与 latest v152.0.7977.75。SDK 通道与 GitHub Latest 分开维护。需要使用指定本地版本时，将 CLOAKBROWSER_BINARY_PATH 设置为可执行文件的绝对路径，即可跳过下载。

为什么源码与下载版本不同？+

源码版本描述各操作系统当前的构建输入，发布标签则标识一组已发布文件。当前 Linux 与 Windows 源码为 154.0.8037.97，macOS 为 152.0.7977.82。Windows x64 / ARM64 及 Linux x64 / ARM64 下载均使用 v154.0.8037.97，仅 macOS x64 / ARM64 继续使用 v154.0.8037.57，等待各自新版发布。Windows ARM64 的 .97 包复用通过原生重验的 216 补丁构建，不包含当前源码中的新 noise 改动。

Docker 镜像现在可用吗？+

原有 154.0.8037.57 标签仍提供双架构镜像。已发布的 ghcr.io/xiaozhou26/chromix:latest 与 154.0.8037.97 标签为 amd64 和 arm64 均提供 154.0.8037.97，原生运行测试与匿名拉取均已通过。版本检查可直接运行；无头浏览需要仓库提供的 seccomp 策略及宿主用户命名空间支持，AppArmor 要求请参阅 Docker 指南。

Chromix 保证通过检测吗？+

不保证。浏览器配置能力不等于匿名性、检测绕过或第三方服务的通过率。请仅在获得授权的范围内使用，遵守服务条款与适用法律，并在自己的环境中验证实际行为。
